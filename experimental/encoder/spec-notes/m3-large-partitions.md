# M3 legal partition traversal for dimensions 17 through 64

Status: partition grammar, boundary range transcript, transform/reconstruction
order, and cropped local reconstruction are integrated in public 17..64
production encoding.

## Normative and independent evidence

Reviewed AV2 v1.0 partition syntax/semantics and official CDF attachments,
pinned AVM revision `966a7d7cd6fcf60360caf5dc413b2aeeb65e144d`,
the project decoder's independent partition/traversal/context implementation,
and executable model `tools/m3_large_partition_model.py`.

Square split is eligible only for 128x128 and 256x256 nodes. It is not a
32x32 or 64x64 choice. For this bounded 64x64 superblock, a non-`NONE`
ordinary partition therefore follows:

1. `do_split=1`, unless boundary logic implies that the node must continue;
2. no `do_square_split` symbol;
3. `rect_type` when the axis is not implied; and
4. with extended partitions disabled, ordinary `HORZ` or `VERT` without an
   extension symbol.

The legal 32x32 four-leaf path is:

```text
32x32 HORZ
  32x16 VERT -> 16x16, 16x16
  32x16 VERT -> 16x16, 16x16
```

At reset top-left state the 32x32 split context is
`2*4 + 0*2 + 0 = 8`; the rectangular-type context is
`3*4 + 0*2 + 0 = 12`.

## Frame and superblock traversal

The frame MI dimension is `2 * ceil(pixels/8)`. Thus dimensions 17..64
collapse to six boundary classes: 24, 32, 40, 48, 56, and 64 coded pixels per
axis. One 64x64 sequence superblock covers this range. Full images extend this
by visiting superblock roots with columns advancing inside each row.
Partition and coefficient left contexts reset at each superblock row; above
contexts persist across rows.

Within a root, traversal is depth first. Nodes wholly outside the rounded
frame MI grid are skipped. Boundary decisions with neither half available are
fully implied. At a partial rectangular boundary, `do_split` is omitted but
`rect_type` can still be coded; choosing the long axis avoids 32x8/8x32
leaves. The model terminates in legal 8x8, 8x16, 16x8, or 16x16 prediction
blocks.

## Contexts and leaf order

```text
split = split_size_adjust*4 + left_smaller*2 + above_smaller
rect  = rect_size_adjust*4  + left_smaller*2 + above_smaller
ext   = split_size_adjust*4 + first_half_smaller*2 + second_half_smaller
```

Each committed leaf writes `64-width_mi` into its covered above contexts and
`64-height_mi` into its covered left contexts. Context arrays are global to
the tile traversal, not reset at prediction-block boundaries.

The leaf list is not globally raster ordered for every shape, so syntax cannot
be generated by flattening to a raster list. Raster reconstruction storage is
still maintainable: exhaustive checks prove every external top/left dependency
is already reconstructed before each leaf. Keep one frame reconstruction
surface, process transforms in leaf-local raster order, and update coefficient
contexts immediately after each transform.

## Transform and reconstruction order

The verified rectangle-only leaf shapes use these 8x8 transform layouts:

* 8x8: one transform;
* 8x16: two transforms, top then bottom;
* 16x8: two transforms, left then right; and
* 16x16: four transforms in local raster order.

Prediction is derived per transform, not once per prediction block. The
project decoder copies the prediction-block mode into each transform leaf,
then calls luma reconstruction with that transform's coordinates. Each call
loads its currently reconstructed top/left samples and commits visible samples
before the next transform is decoded. Thus the second transform in a 16x16
leaf can use the first transform as a neighbor.

For 32x32 the beginning of decoder sample order is:

```text
(0,0) (8,0) (0,8) (8,8)
(16,0) (24,0) (16,8) (24,8)
```

It is not the global raster order:

```text
(0,0) (8,0) (16,0) (24,0) (0,8) ...
```

This is why the prior local 32x32 SSE diverged. Levels and local samples were
selected in global raster order, while the rectangular entropy traversal made
the decoder consume that level sequence in leaf-local order. The first
misassociated level is transform index 2. On the frozen non-flat 32x32 vector,
the correctly ordered active SSE is `5376226`; replaying the legacy level
sequence in decoder order gives `5609644`.

## Coefficient contexts

The decoder queries coefficient state for every transform using the transform
node plus its containing prediction-block size. For luma, an 8x8 transform
that is the whole prediction block uses all-zero context 0. A transform inside
a larger rectangle uses the normative 5x5 table indexed by the capped OR of
the top and left `cul_level` values. DC sign context sums sign flags from every
covered top and left MI entry: negative gives 1, positive gives 2, balanced
gives 0.

After each transform, its two-by-two MI region receives
`min(7, abs(level))` plus bit 3 for negative DC or bit 4 for positive DC.
The executable trace proves this update happens before the next transform and
before the next prediction leaf.

## Source edges, coded canvas, and crop

The encoder objective edge-extends source samples to
`8*ceil(width/8)` by `8*ceil(height/8)` by repeating the last active column
and row. The local reconstruction may retain this complete coded canvas.
The decoder commits only `min(8, frame_edge-position)` visible samples.
For DC prediction, a short visible top/left edge is extended from its last
reconstructed sample. With DC-only 8x8 reconstruction, this is byte-identical
to reading the local coded canvas. The final public reconstruction and SSE are
the active `width*height` crop.

The independent model executes both storage strategies in lockstep and proves
identical predictions and cropped bytes for all ten odd, rectangular, and
square representatives. It also runs inverse DC dequantization, inverse DCT,
clipping, context updates, and active-pixel SSE without calling production
`m3.c`.

## Executable verification

`test_m3_large_partition_model.py` exhaustively checks all 2,304 dimension
pairs 17..64 for exact active-grid coverage, legal leaf shapes, absence of
square-split symbols, eight-pixel class equivalence, and dependency safety.

The original AVM probe forces min/max prediction partition size 16, disables
extended and uneven partitions, and encodes flat-128 I400 for every 6x6
rounded class. All 36 streams were accepted by pinned `avmdec` and the project
decoder; both emitted identical exact flat-128 planes in every case.

A second frozen probe uses the deterministic non-flat source pattern for ten
representative dimensions. Pinned `avmenc` and `avmdec` accept all ten and
emit the exact active sample count. The project decoder currently returns its
diagnostic `integer overflow` for every stream when a nonzero inverse
transform is reached (for example 32x32 reports leaf `(0,0)`, block 6,
`eob=64`, coefficient stage 12). This is a project-decoder implementation
limit, not an AVM conformance failure; source inspection remains the
independent evidence for reconstruction order. The failure is frozen rather
than hidden in `tests/m3_multileaf_avm_probes.json`.

## Production integration

The legal path, adaptive entropy state, depth-first leaf emission, and local
reconstruction now drive The production encoder extends this model across row-major 64x64 superblocks.
Partition and coefficient left contexts reset at each superblock row, above
contexts persist for the tile width, CDFs remain tile-wide, and reconstruction
neighbors cross superblock boundaries.

The former integration mismatch is exact: terminal 8x8 boundary leaves
used split context 4 instead of 0. The private correction passes both decoders
for flat and non-flat 24/32/40/48/56/64 classes. See
`m3-boundary-partition-transcript.md`. Full-image/multi-superblock promotion
is complete through the 1440-per-axis production bound.
